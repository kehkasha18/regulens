# ReguLens

## Evidence-Grounded Regulatory Intelligence for the EU AI Act

ReguLens is a Retrieval-Augmented Generation (RAG) application that helps users ask questions about the European Union Artificial Intelligence Act.

The system retrieves relevant provisions from a locally indexed copy of the EU AI Act, evaluates the relevance of the retrieved content, and presents an answer together with the supporting regulatory evidence.

ReguLens is designed to prioritize source-grounded responses and reduce unsupported or unrelated answers.

---

## Overview

Regulatory documents are often lengthy and difficult to navigate. ReguLens provides a question-answering interface that allows users to search the EU AI Act using natural language.

Instead of answering from unrestricted general knowledge, the application:

1. Receives a user question.
2. Checks whether the question is related to the EU AI Act.
3. Converts the question into an embedding representation.
4. Retrieves relevant regulatory provisions from ChromaDB.
5. Evaluates the relevance of the retrieved provisions.
6. Selects applicable evidence.
7. Generates a grounded answer.
8. Displays the answer with supporting regulatory excerpts.

If a question is unrelated to the EU AI Act, ReguLens rejects it rather than providing a general-purpose answer.

## Preparing the Knowledge Base

Before running the application for the first time, create the local vector database by running:

```powershell
python ingest.py
```

The ingestion process performs the following steps:

1. Reads the local EU AI Act HTML file.
2. Removes unnecessary HTML elements such as scripts and styles.
3. Extracts the document text.
4. Detects individual article headings.
5. Extracts article titles and article content.
6. Creates one searchable chunk for each article.
7. Adds metadata such as:
   - Article number
   - Article title
   - Regulation name
   - Document version
   - Official source URL
8. Creates or rebuilds the ChromaDB collection.
9. Stores the indexed provisions in:

```text
data/compliance_db/
```

The ingestion script rebuilds the collection so that outdated or previous local provisions are removed before the current source document is indexed.

## Understanding the Retrieval Scores

### Rerank Score

The rerank score represents the relevance assigned to a retrieved provision after the relevance-processing stage.

A higher score generally indicates that the provision is considered more relevant to the submitted question.

For example:

```text
Rerank score: 0.555212
```

This score is used as an internal relevance signal. It should not be interpreted as a percentage or probability.

### Semantic Distance

Semantic distance represents how far the question embedding is from the retrieved document embedding in the vector space.

A lower distance generally indicates greater semantic similarity between the question and the retrieved provision.

For example:

```text
Semantic distance: 0.47438478469848633
```

Semantic distance is not a legal confidence score. It is a retrieval-related similarity measurement.

## Scope Control

ReguLens is designed specifically for questions related to the EU AI Act.

For example, a question such as:

```text
How is the weather in Delhi?
```

is outside the scope of the knowledge base.

The application responds with a scope message instead of generating an unrelated answer.

This prevents the system from behaving like an unrestricted general-purpose chatbot.

---

## Grounding Principle

ReguLens prioritizes evidence grounding over unrestricted answer generation.

The application is designed to:

- Use retrieved regulatory provisions as the basis for answers.
- Display the evidence supporting the answer.
- Avoid answering unrelated questions.
- Communicate when sufficiently relevant evidence is not available.
- Preserve the connection between the answer and the underlying legal text.

The system does not claim to replace legal research or professional legal advice.

## Current Implementation

The current version uses article-level indexing.

Each detected article is stored as one searchable chunk in ChromaDB.

For example:

```text
Article 5  → One searchable chunk
Article 16 → One searchable chunk
Article 26 → One searchable chunk
Article 50 → One searchable chunk
Article 99 → One searchable chunk
```

Each chunk contains both the article text and metadata describing the source.

## Limitations

The current implementation has the following limitations:

- It focuses on the EU AI Act only.
- It uses article-level chunks rather than paragraph-level chunks.
- It uses a local ChromaDB database.
- It does not provide legal advice.
- It does not guarantee complete legal interpretation.
- Retrieval quality depends on the quality and version of the indexed source document.
- The document version should be checked against the official EUR-Lex source before making compliance decisions.
- The application is intended to support regulatory exploration and evidence review, not replace professional legal analysis.
